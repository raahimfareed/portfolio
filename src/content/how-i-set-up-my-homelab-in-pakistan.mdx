## Getting Everything Connected: The Actual Network

I'm by profession a Software Engineer, and by hobby a gamer. I had 0 interest in computer networks until I actually setup my own server. Now, you don't have to know everything, I certainly don't, but it helps knowing some basics (which I won't teach because.).

### Operating System
To actually start working, I first installed Ubuntu 24 LTS. It's a distribution of linux. This is preferred over windows for servers because it has high security, it's very stable, has good docker support (we use this a lot in self hosting) and it's free (open source baby!).

### Unmanaged Switch

In a previous section, I mentioned how I bought a TP-Link unmanaged switch. Think of it as an ethernet port extender. It's just that in simple words. Have less ports? Just add an unmanaged switch. There's more to it of course, but for our use case, this is exactly what it is.

How does it work though? Simple, It has N amount of eth ports, in our case 5. Plug one end of the eth cable into your main router, and the other end in ANY eth port of the unmanaged switch, it doesn't matter which one. For cleanliness and order I plugged mine into the left most port.

Once that is done, I connected both my PC and my homelab server into free ports in the switch and finally connected the switch adapter into my extension board.

That's about it.

### Cloudflare Tunnel

If we want to access our services from outside our own network, we need either of the two things
- A static IP (and optionally a domain)
- A tunnel (and definitely a domain)

If you have a static IP, great, use that. Don't know if you have a static IP? Call your ISP (PTCL, Nayatel, etc) and ask them whether you have one or not. If not, ask them if they provide one and for how much. This is something that you'll need to assess on your own based on your internet provider, your internet plan, and if the static IP is an add on, whether it is in your budget or not.

If you don't have a static IP (like me), you can opt for the tunnel path. It MAY be possible to use tunnels without domains, but I'm not sure about it. Personally, I use my domain raahimfareed.com for the tunnels. So for my git instance, I just have my own subdomain, [git.raahimfareed.com](https://git.raahimfareed.com/).

If you want a cheap domain, you can get a numeric xyz domain from [PorkBun](https://porkbun.com) or [Spaceship](https://spaceship.com). Since it's an international transaction, only Visa/Mastercard cards will work. In my experience Nayapay works just fine if you don't have a proper bank card. In order to qualify for the cheap/discounted rate, your domain needs to
- Have ONLY numbers
- Length should be 6 to 9 numbers
- Should be a .xyz domain

This costs roughly Rs. 200 per year which is very cheap if you just want to test homelab without commiting to a domain.

Okay, now we have a domain, and a cloudflare account AND we've transfered DNS Nameservers to Cloudflare for our domain, what's next?

We need to install `cloudflared` on our homelab. There are many ways to do this, I personally installed it as a `systemd` service, but you can use docker if you like. I recommend just using ChatGPT or Claude to guide you through this if you're non-technical.

Once cloudflared is setup and active, new sub domains can be registered in the cloudflare zero trust dashboard.

### Camera

For Tapo series, you need to use TP-Link Tapo app to setup the camera (which kinda sucks). Once that is done, there's an option in the settings to setup camera account, that's the important one. Once you have a camera account (RTSP credentials) and you've set the gateway of the camera as your homelab IP, you can safely disable/delete the app. I personally archived my app because I didn't need it anymore after setting up a camera account. Note, that the RTSP credentials are important, that's what allow you (or other applications like frigate) to access the camera outside of the Tapo application.

With the homelab IP set as the gateway IP in Tapo app, all of the camera traffic will go through the homelab itself. This gives us the power of blocking cloud access of the camera. Some people like cloud access, more power to them, I don't. It's kind of eerie to have a camera sending the feed somewhere on the internet. Due to that, I personally blocked ALL outbound requests from the camera in my homelab.

The camera itself connects to a software called Frigate (will get to it in a later section), which handles all cameras' live feeds and recordings as well as object detection and camera movement if your camera supports it.

### How Does Everything Communicate with Each Other

Now that we've everything connected, the router has assigned local IP addresses to each device.

So the router itself has an IP address which is called the gateway IP: `192.168.1.1`

Whatever connects to the router, gets an IP address in this format `192.168.1.x`, so for example  
My PC got: `192.168.1.49`  
My homelab got: `192.168.1.101`  
My thinkcentre got: `192.168.1.77`  

These IP addresses are like house addresses. To send a parcel, you need their house address, to access the computer, you need its IP.  
Let's continue this analogy, each house has multiple people, same way, each computer has multiple ports. A port is just a number where some kind of application runs

For example, your own notes app is running on port 3000, your google photos replacement is running on port 5000 and your password manager is running on port 9000, how will we access the google photos replacement? We'll type `192.168.1.101:5000` in our browser (like chrome or opera gx).

This is all well and good, you can access your apps that you hosted on your homelab, perfect, but we've run into a problem, as soon as you disconnect from the WiFi (Or leave your computer), the IP and port stops working. That's because, the IPs assigned by your router are internal/private IPs. They're only accessible as long as you're connected to the router either by WiFi or through ethernet.

This is why we use cloudflare tunnels, to connected a website URL or a subdomain to an IP and Port. This way any internal app can be accessed from the outside.

One thing to keep in mind is that, some things should NOT be public, like your databases, NVR, anything that unauthenticated. If you're assigning a tunnel to an app, use your judgement on whether it should be public or not.

## Backup Strategy

In the start, when this was just a means of testing a new hobby out, I didn't care much about the data on it. Which is fine, nothing important on it, it can easily be re-set-up if need be.

That was the past, I now use it for all my photos, and my git repositories. Data safety is critical now. This is where data backup comes in.

The gold standard for keeping data safe is the 3-2-1 framework.

- 3 copies of data
- 2 different types of media
- 1 copy offsite

In these backups/copies I usually do the following

- Small files backup: Config files, .env files (these have all the secret passwords), database dumps
- Large files backup: Actual photos library
- Git backup: Git repositories, I back these up, just not in the same backup media as other things
- Don't back up: media and song library. These can be redownloaded from the internet again, don't need them taking up extra space in a backup
- Everything else, don't backup

I've done just the 3 (some of it) and the 1.

I have setup `restic` which is a backup tool. I've setup 2 [Backblaze B2 Buckets](https://secure.backblaze.com/b2_buckets.htm). For technical folks, this is an S3 compatible storage. AWS has S3, Cloudflare has R2, Backblaze has B2. S3 is the most expensive, R2 is reasonable and B2 is the cheapest, which is why I went with B2. 1TB/month is around 6.95USD which is like Rs. 2000 but the good thing is, it only charges for storage that is being used, and first 10GB is free.

So for example, I have 100GB of backup, first 10GB is free, and the remaining 90GB costs me around 200 rupees.

For starting out, since you'll only have config files, they'll be well under 10GB so backups would be completely free.

Back to the actual backup,  
This becomes my off site and 2nd copy. I have setup RAID 1 on my server but at the moment only have 500GB and 1TB of drives. It'll start working once I attach another 1TB drive. The server will use one of the drives as a redundancy drive, it'll just have a duplicate of all the data. This is done so, incase one of the drive fails, the other keeps working. The only con is, even though I have 2x 1TB drives, I can only use 1TB storage instead of combined 2TB storage (basically half the storage). Once RAID 1 is in action, that'll be the 3rd copy, fulfilling the 3-2-1 rule.

For my git repos, set up mirrors on forgejo to automatically push to github. GitHub acts as a backup for my repos. I push all my changes to my own git instance, which syncs to GitHub on its own.

With all that being said, backups are an additional *necessary* cost if you have critical data on the server.
